# 多步预测漂移优化方案（架构师 + 深度学习专家双视角）

> 本文是对整个工程的双视角分析与针对「多步预测漂移（rollout 误差随步数累积）」的优化工程方案。
> 分析基于 2026-08 对仓库的全面只读审查，关键论断均标注源码位置。只做方案落盘，不含代码改动。

## 0. 工程概况

基于物理先验 Koopman 算子的船舶速度多步预测 + 潜空间 QP-MPC 控制。

- 模型谱系 v1→v2→v3/v3a→v4（当前主推），统一为 `z + A(z) + B(u)` 欧拉残差形式（有效矩阵 Ā=I+A_w）。
- v4 潜空间 48 维 = dict16 物理原子 + hidden(32)，decoder MLP 重构状态（`new_v4_dict_input/model_v4_dict_input.py:97,110-116`）。
- 训练：Python/PyTorch（v1~v3 在 `koopman/` + `scripts/`，v4 在 `new_v4_dict_input/`）。
- 部署：C++ `cpp/koopman_control`（OSQP 潜空间 condensed QP-MPC）+ `cpp/koopman_mpc`（ONNX plant）。
- 当前部署配置：v4 dt=4s 变体，horizon=10（40s），`opt_control_steps=2`（`cpp/koopman_control/config/mpc_config.yaml:5-6`）。

## 1. 架构师视角分析

### 1.1 做得好的地方

- 模块依赖基本单向：数据（`scripts/data/`）→ 训练 → 模型库（纯 `nn.Module`）→ 评估（`koopman/evalkit.py`）→ 导出 → C++。
- 发散指标是一等公民并**参与模型选型**：`ratio / slope_loglog / lyapunov_like / instability_score`（`koopman/evalkit.py:395-447`）直接进入 best-ckpt composite（`train_v4_dict_input.py:1029-1031`）。
- 训练→导出一致性机制扎实：ckpt 内嵌 args/stats/model_class；ONNX 导出带 PT/ORT 双重校验（atol=1e-4）与 `rollout_check.npz` 供 C++ 对照（`export_v4_onnx.py:445-481,611-624`）。

### 1.2 关键架构问题

1. **三套并行 rollout 实现**（训练 `train_v4_dict_input.py:298-324`、评估 `evalkit.py:208-310`、导出 `koopman/export/rollout.py:12-55`），一致性靠注释与 `tests/test_rollout_equivalence.py` 维持，属脆弱耦合。
2. **best checkpoint 选择口径随 curriculum 漂移**：验证 rollout 用当前 curriculum 的 `pred_len`（`train_v4_dict_input.py:1013`），而 `best_metric` 跨阶段累积从不重置（`:1089-1094`）。扩窗瞬间指标系统性变差 → best 几乎不再更新，**最终部署的可能是短 horizon 口径选出的模型**。
3. **C++ 部署链两处静默风险**：
   - `u_prev` 在实船链路从未接入（`cpp/motion_koopman_mpc.cpp:19-41` 不写 `has_u_prev`），首块速率约束静默锚定物理零控制，按训练统计换算首步油门被钳在物理 ±15、舵 ±3.5° 内；`docs/v4代价函数设计分析.md:282` 已记录此问题（P0-1，实测代价 +54%）。
   - dt 语义陷阱：ONNX 图内 `latent_step` 步长固化等于训练 dt，`mpc_config.yaml` 的 dt 仅用于位姿欧拉积分（`koopman/export/rollout.py:47-53`、`mpc_controller.cpp:16-33`）。误用旧 H=200@dt=0.1 的 ONNX 时 `states[1]` 只推进 0.1s 动力学却积分 4s 位置——**静默失配，无运行时检查**。
4. **漂移按幂次烘焙进 QP**：`precomputePredictionMatrices` 把 Ā¹..Āᴺ 缓存为 Γ/Θ/ξ（`koopman_latent_model.cpp:77-128`），Hessian `H = w_z·ΘᵀΘ + ...` 永久缓存（`latent_mpc_qp.cpp:120-163`）。模型多步漂移在部署前就已定型在 QP 里；`opt_control_steps=2` + 尾部保持正是对长 horizon 不信任的设计佐证。
5. **闭环仿真自证不了模型质量**：`simulate()` 的 plant 就是同一模型的 ONNX rollout（`mpc_controller.cpp:216`），"模型控模型"，多步漂移在仿真闭环中被掩盖。
6. 工程卫生：`evalkit.py` 1936 行巨型文件；`load_v4_model` 等函数三份拷贝；`merge_yaml` 对 `--epochs=120` 等号形式识别失败导致 YAML 静默覆盖 CLI（`train_v4_dict_input.py:685-687`）；`ONNX导出说明.md` 的 horizon/dt 口径已过时；OSQP 求解失败直接抛异常（`latent_mpc_qp.cpp:368-372`），实船无降级兜底。

## 2. 深度学习专家视角分析

### 2.1 漂移的真实形态（实证）

- **不是数值发散**：把 ρ 压到 0.9993<1 后 K=20 误差曲线几乎不变（`docs/工程全景说明文档.md:739`）。现役 v3/v4 全部模态 |λ|<1（v4 实测 ρ=0.99982），漂移只能是偏置型/相干累积，而非指数发散。
- **窗内不漂、窗外漂**：dt=1s 下 step1→20 仅 +3%（0.0149→0.0154），step200 达 11×（0.1664）；`u_bias` 从 +0.0033 单调漂到 −0.0188 m/s（`eval_out/mmg_compare/koopman_v4_per_step.csv`）。
- **末段误差相干性上升**：|bias|/rmse，v 通道 0.17→0.41、r 通道 0.01→0.31（k=1→10）——末段误差从随机噪声转为准系统偏差（`docs/v4多步训练代价函数分析.md:111-117`）。
- **误差剖面呈 U 型**：首步 v 误差是第 5 步的 3.1×，slope_loglog=−0.118（同文 `:98-105`）。

### 2.2 根因定位（按贡献排序，均有量化证据）

1. **位姿项 L_xy 劫持训练（主因）**：L_xy 占加权损失 95.8%、梯度范数 98.4%（量纲问题：物理米² O(5) vs 归一化 Huber O(0.1)，w_xy=2 再放大）；grad-clip=1.0 把其他项裁剪抹掉（cos(∇L,∇L_xy)=+0.9999）。**消融已验证：关掉位姿项 vel_rmse −38%~−47%，traj_xy@10 也 −19%~−23%**（`docs/v4代价函数设计分析.md` §1.2-1.3）。curriculum 扩窗使 L_xy 随 K 近似二次增长（K=1→10 放大 92.6×，占比 26.9%→95.9%），训练越后期越偏位姿（`docs/v4多步训练代价函数分析.md` §5）。
2. **相干偏差无约束**：v3a 的 `L_bias`（逐步批均值偏置平方）与 `L_slope`（log-log 斜率惩罚）在 v4 中被删除（`docs/训练流程指南.md:76-77`），而末段误差恰好偏差主导。
3. **无任何抗累积正则**：部署 ckpt `noise_std=0`、`ctrl_noise_std=0`，无 scheduled sampling——模型只见过"从真实 t₀ 出发"的轨迹，闭环自馈分布偏移零对冲。噪声增强代码已就绪（`train_v4_dict_input.py:347-348`）但从未启用过。
4. **ZOH 输入失配构成误差下界**：1s/4s 块只取块首控制（`train_v4_dict_input.py:213`），45.2% 窗口块内指令非恒定，高机动段误差 1.87×（偏相关 +0.283）——口径性误差，损失优化消不掉（`docs/v4多步训练代价函数分析.md` §6）。
5. **数据分布与部署错位**：zigzag 占训练帧约 64%，直航/小舵（MPC 巡航常见工况）不足 10%；4 维控制在 81/99 段退化为 2 维（左右舷油门相同）；控制实为执行器反馈（`/system/chassis_feedback`）而非下发指令；MPC 产生的平滑小幅序列属分布外。**v4 把测试集当验证集做 best 选择**（`--test_data=P.TEST`，`koopman_val.npz` 闲置）。
6. **ρ 贴单位圆**：v4 实测 ρ=0.99982，`rho_max=1.005` 允许慢模态；L_stab 平方罚在边界处梯度消失、名存实亡（部署 ckpt ρ=1.0055>ρ_max 但 L_stab=2.5e-7）。
7. **其他损失层问题**：`L_recon` 只施加在 t₀ 单点；`L_lin` 目标 `encode(target)` 未 detach（moving target）；`L_acc` 漏乘步权；`gamma_step=0.97` 与末端精度目标相悖。

## 3. 优化工程方案

### P0 — 口径修复（零风险、消融已验证收益，预计 1~2 天）

| # | 改动 | 位置 | 预期收益 / 依据 |
|---|------|------|----------------|
| P0-1 | `w_xy` 从 2.0 降到 ≈0.019（等份额标定）或先置 0 | `train_v4_dict_input.py:588` | 消融已验证 vel_rmse −38%~−47%，且 traj_xy 同步改善 |
| P0-2 | 恢复相干偏差约束：移植 v3a 的 `L_bias` + `L_slope` 回 v4 | `train_v2.py:431-467` → v4 | 直接约束末段准系统偏差（当前无任何损失项覆盖） |
| P0-3 | curriculum 到达 `pred_len_max` 时重置 `best_metric`；composite 加入 slope_loglog 或末端 RMSE 项 | `train_v4_dict_input.py:1089-1094,1029-1031` | 保证 best 选择口径 = 部署口径 |
| P0-4 | 开启噪声增强 `noise_std=0.02~0.03`、`ctrl_noise_std=0.003~0.005`，按 `docs/数据增强技术方案.md` §5.2 做 on/off 消融 | `train_v4_dict_input.py:596-608` | 建立闭环分布偏移对冲；代码已就绪 |
| P0-5 | C++ 实船链路接入 `u_prev`（缓存上一拍下发控制），或缺失时把首块速率约束显式松弛 | `cpp/motion_koopman_mpc.cpp:19-41` | 消除首步油门静默钳位（已记录实测代价 +54%） |

### P1 — 机制修补（低风险，约 1 周）

| # | 改动 | 说明 |
|---|------|------|
| P1-1 | 控制聚合由块首改为块内均值/中值；dt=4s 配置先评估离散化误差 | 消除 ZOH 口径性误差下界 |
| P1-2 | `L_stab` 换线性罚或谱投影（`rho_max=0.999` 留余量）；`L_recon` 扩到全程；`L_lin` 目标 detach；`L_acc` 补步权或 dt=4s 下删除 | 修复损失层已知缺陷 |
| P1-3 | 数据侧：v4 恢复独立验证集（best 用 `koopman_val.npz`，test 只做终审）；录制 `/control/control_cmd` 替代反馈当指令；补采/仿真 MPC 风格平滑小机动数据（或 DAgger 回灌）；直航/小舵占比提升或移植 `seg_resample` 到 v4 | 消除开环→闭环分布差与选择偏差 |
| P1-4 | 评估补度量：窗内/窗外分段 slope、|bias|/rmse 逐步曲线入 evalkit、ratio 改用 step5 做基准、U 型剖面形状标志位、各 run 评估 JSON 随 ckpt 落盘 | 现有单一 ratio 掩盖"窗内平、窗外漂"的真实形态 |
| P1-5 | 工程收敛：三套 rollout 合一（噪声/反归一化作开关）；`load_v4_model`/`write_per_step_csv` 提为公共模块；修 `merge_yaml` 等号检测；latent YAML 增加 dt 字段并与 `mpc_config.yaml` 启动交叉校验；OSQP 失败加"保持上一拍控制"降级；同步更新 `ONNX导出说明.md` 口径 | 消除静默失配点 |

### P2 — 范式级（等 P1 闭环裁决后再投入）

| # | 改动 | 说明 |
|---|------|------|
| P2-1 | **S-KMPC 终端代价**（只改 QP 的 P/q，文档自评"性价比最高"） | 可与 P0 并行推进 |
| P2-2 | MMG+残差混合模型部署链路（开环 200 步外推 RMSE 0.0096 vs v4 0.166，低 17 倍；缺 `export_mmg_residual_onnx.py`） | 用同口径闭环对比裁决是否换建模范式 |
| P2-3 | 多步 EDMD（直接辨识 condensed 矩阵，绕开 Āᵏ 幂次累积，arXiv:2601.11901）、ConsKAE 前后向一致性、非线性 latent step | 突破线性潜空间 slope≈0.70 下界的候选 |

**明确不优先的方向**：DISKO/谱约束类文献方法。本工程已实证长程漂移是控制驱动的相干误差累积而非谱发散（ρ<1 后曲线几乎不变），纯谱路线压不平长程曲线，不要在此重投。

## 4. 验证闭环

1. 每项改动固定同一 test 集 + 同一逐步评估协议；
2. 验收四指标：step20 内 RMSE、step200 漂移率、分段 slope（窗内/窗外分开拟合）、|bias|/rmse 逐步曲线；
3. 训练侧修复全部完成后，以 **MPC 闭环跟踪误差**（而非开环指标）作为漂移问题的工程终审；
4. 上实船前必须通过 P0-5 与 latent YAML dt 交叉校验，避免静默失配上线。
